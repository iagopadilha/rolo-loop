Unsupervised /orchestrator loop

positional arguments:
  repo

options:
  -h, --help            show this help message and exit
  --wave WAVE           features (lanes) in parallel per turn, each with its
                        own agents at every step (execution only with disjoint
                        PATHS and met dependencies); default 3
  --e2e                 authorizes the final flow-validation phase (verifier-
                        flow, headless)
  --push                requires the final push+PR (fails the preflight if
                        there is no remote/identity). Without the flag push+PR
                        is already the DEFAULT (feature branch only)
  --no-push             do not push the branch nor open a PR at the end
  --budget BUDGET       max US$ per turn
  --timeout TIMEOUT     max minutes per turn
  --max-stall MAX_STALL
                        consecutive turns without progress before stopping
  --limit-wait LIMIT_WAIT
                        minutes to wait when the usage limit is hit
  --limit-retries LIMIT_RETRIES
  --permission-mode PERMISSION_MODE
                        auto | acceptEdits | dontAsk
  --branch BRANCH
  --base-branch BASE_BRANCH
                        branch new worktrees start from and the PR target (the
                        ROADMAP `Branch base`); default: LOOP_PR_BASE /
                        LOOP_INTEGRATION_BRANCH, else developer
  --git-user GIT_USER   requires this git user.name on push (or LOOP_GIT_USER
                        in the app .env); default: any configured account
  --setup SETUP         one-time command after creating the worktree (e.g.
                        "npm ci")
  --claude CLAUDE       claude binary (or a test .py)
  --claude-fallback COMMAND
                        command tried when the running one hits the account
                        usage limit (repeatable, in order; e.g. `cc`, a
                        wrapper signed in with another account)
  --option N            answers the question by the NUMBER of the option
                        listed in the notice (same as --answer with that
                        option's text)
  --answer ANSWER       answers the question that stopped the loop
                        (awaiting_user) and continues; goes to ANSWERS.md
  --instruction TEXT    the same as --answer, named for the states that are
                        not a question: also accepted when the run is paused,
                        done or in error; the next turn applies it
  --max-cost MAX_COST   cap of US$ summed over all turns (0 turns it off); a
                        cap raised in the panel (meta max_cost_usd) wins; when
                        exceeded the loop PAUSES (resumable)
  --orchestrator-model ORCHESTRATOR_MODEL
                        model of the orchestrator turns (--model of claude);
                        empty = no flag, the CLI default
  --rewind N            go back to the state right after turn N (state files +
                        git reset --hard of the loop branch). Without --yes it
                        only shows the plan
  --yes                 confirms --rewind
  --leftovers {commit,discard}
                        uncommitted files outside .specs/ left in the
                        worktree: commit them all as a checkpoint or discard
                        them, then carry on (the panel's recovery buttons)
  --summary-dir SUMMARY_DIR
                        folder of the final summary (default: the app's output
                        folder, ~/Downloads when unset)
  --json                with --check: after the text lines, print one `[check]
                        JSON: {...}` line with problems, warnings and `items`
                        (kind, repo, files, text, fix)
  --check               only checks the preflight, prints the ready command
                        and exits (creates nothing)
  --planning            with --check: readiness of a roadmap NOT yet approved
                        (skips the approval, adds worktree, feature-path, MCP,
                        credential and test-command checks)
  --dry-run
  --ensure-worktrees    only creates (or re-attaches) the worktrees as the
                        loop start does, prints the `[loop] [<repo>] <kind>:
                        <text>` lines and exits; no preflight, no turn
  --repos REPOS         with --ensure-worktrees: comma-separated repo names to
                        create (the primary is always ensured)
  --continue-on-blocked
                        a quarantined feature NEVER pauses the loop, not even
                        when another depends on it
  --pause-on-blocked    a quarantined feature ALWAYS pauses and notifies (this
                        is now the default; kept for compatibility; formerly:
                        only pauses when another feature depends on the
                        blocked one)
  --allow-silent        testing only: waives the mandatory notice channels
                        (LOOP_NOTIFY_REQUIRED)
  --no-auto-answer      turns the automatic answer off: every orchestrator
                        question stops the loop and waits for you (default:
                        the script answers on its own the ones that do not
                        need you)
  --no-monitor          does not start the loop web panel (default: starts on
                        its own; also off with LOOP_MONITOR=off in the app
                        .env)
  --gate-tiebreaks GATE_TIEBREAKS
                        gate tiebreaks per feature: after several rejections
                        the script tells the orchestrator to approve the spec
                        and run it (0 turns it off)
  --max-auto-answers MAX_AUTO_ANSWERS
                        cap of automatic answers per script run
  --auto-answers-per-feature AUTO_ANSWERS_PER_FEATURE
                        cap of automatic answers for the same feature (avoids
                        spinning forever on a gate that rejects)
